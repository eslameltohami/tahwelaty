# TAHWELATY — تحويلاتي

واجهة عربية RTL لتحويلات الأموال وسداد الفواتير. يحتوي المشروع على واجهة React Native لـAndroid/iPhone ونسخة React DOM مستقلة للويب وPWA.

## الحالة وحدود الأمان

هذه **نسخة واجهات تجريبية** وليست خدمة مالية أو تطبيقًا جاهزًا للإطلاق. الرصيد الظاهر صفر جنيه؛ والعمليات محاكاة محلية فقط. لا يوجد مزود دفع أو اتفاق API أو Sandbox، ولا يرسل التطبيق أموالًا أو بيانات أو شكاوى إلى بنك أو شركة تحصيل. لا تستخدم بياناتًا مالية حقيقية عند تجربة النماذج.

تظهر فوري وأمان ومصاري وe-Khales كأمثلة سوقية غير مرتبطة بـTAHWELATY. وتظهر شركات الفواتير كخيارات تصميمية فقط؛ لا يوجد استعلام فاتورة أو دفع فعلي. مصادر الأسماء موثقة في [`docs/egypt-biller-sources.md`](docs/egypt-biller-sources.md).

PIN التجريبي يُحتفظ به في ذاكرة الجلسة فقط ولا يحمي أموالًا. يتطلب التحقق البيومتري هاتفًا يدعم بصمة أو Face ID ومسجلًا عليه قياس حيوي؛ نسخة المتصفح لا تختبر حساسًا فعليًا. لا تعتبر هذه النسخة تطبيقًا آمنًا للإنتاج.

## مشاركة الإيصال كصورة

من حوار الإيصال اختر «مشاركة الإيصال كصورة». على Android/iPhone يلتقط التطبيق بطاقة الإيصال ويعرض قائمة المشاركة النظامية كملف PNG. على الويب يستخدم مشاركة الملفات من المتصفح إذا كانت مدعومة، وإلا ينزّل PNG. تحتوي الصورة على علامة «تجريبي — غير صالح كإثبات دفع» و«لم يتم تنفيذ أي معاملة»، وتخفي معرف المستلم. لا تُرسل الصورة أو البيانات إلى خادم، والمشاركة لا تجعل العملية دفعًا حقيقيًا.

## معاينة الويب والإضافة إلى الشاشة الرئيسية

مصدر واجهة المتصفح هو `app/(tabs)/index.web.tsx` ومكونات `components/tahwelaty-web/`. أما `app/(tabs)/index.tsx` فيظل مسار Android/iOS. افتح Preview للمشروع من لوحة المشروع لعرض نسخة الويب على هاتف أو كمبيوتر؛ تعمل معاينة Expo على المنفذ 8081.

على Android، افتح المعاينة في Chrome واختر «إضافة للشاشة» داخل التطبيق أو «تثبيت التطبيق» من قائمة المتصفح. على iPhone، افتحها في Safari، اضغط «مشاركة»، ثم «إضافة إلى الشاشة الرئيسية». يعتمد ظهور خيار التثبيت على المتصفح ونظام التشغيل. الـService Worker شبكي فقط ولا يخزّن مدخلات أو معاملات مالية، لذلك لا يوجد وعد بتشغيل كامل دون اتصال.

## تشغيل المشروع وفحوصه

```bash
pnpm install
pnpm dev
pnpm check
pnpm lint
pnpm exec expo export --platform web
```

يبدأ `pnpm dev` Expo Web على المنفذ 8081 وخادم القالب على 3000. لا تعتمد التدفقات المالية على خادم القالب ولا يوجد تكامل دفع حقيقي. لمعاينة تطبيق Android/iPhone الأصلي افتح المشروع في Expo Go؛ ويجب اختبار البصمة على جهاز فعلي مدعوم.

## نشر GitHub Pages داخل مجلد المستودع

يتضمن `.github/workflows/deploy.yml` بناءً ثابتًا لـExpo Web يكتشف اسم المستودع تلقائيًا ويضبط بادئة مثل `/tahwelaty`. يدعم الكود التشغيل على جذر Preview وعلى مجلد GitHub Pages، بما في ذلك صورة البداية والأيقونات وManifest وService Worker. لا تعدّل مسارات هذه الأصول إلى `/images/...` أو `/icons/...` يدويًا؛ استخدم `publicAssetPath` والمسارات النسبية في `public/manifest.webmanifest`.

لتطبيق النسخة الحالية على `https://eslameltohami.github.io/tahwelaty/`، استبدل مصدر المستودع بالنسخة الكاملة الحالية، بما فيها مجلد `.github/workflows/`، ثم ارفعها إلى الفرع `main`. من إعدادات المستودع افتح **Settings → Pages** واجعل **Build and deployment → Source** هو **GitHub Actions**. سيبني الـWorkflow مجلد `dist` وينشره. لا تستخدم خطوات `sed` القديمة التي تغيّر `public/manifest.json` أو `apple-touch-icon.png`؛ هذه الأسماء لا تطابق ملفات المشروع الحالي.

إذا ظل الموقع يعرض رصيد 12,450 أو اختفت الصور بعد النشر، فهذا يعني أن Pages ما زالت تخدم مصدرًا قديمًا أو أن أحدث Workflow لم يُنشر؛ تحقق من نجاح آخر تشغيل في **Actions → Deploy TAHWELATY to GitHub Pages**، ثم أعد تحميل الصفحة من دون Cache. قيمة `eas.json` تخص بناء APK وليست سبب تعطل GitHub Pages.

## APK لنظام Android

يهيئ `eas.json` ملف البناء `preview` ليكون توزيعه داخليًا ونوع مخرجه APK. بعد تسجيل/حفظ أحدث مصدر، يبدأ بناء Android من لوحة المشروع Dashboard فقط. لا ينشئ `pnpm dev` أو معاينة الويب ملف APK. لا تسلّم ملف APK إلا بعد ظهور نتيجة بناء ناجحة ووجود artifact قابل للتنزيل؛ وتثبيت نسخة فوق نسخة موجودة يتطلب توافق توقيع Android.

حتى بعد بناء APK، ستظل التحويلات وسداد الفواتير تجريبية ومعطلة ماليًا إلى أن يتوفر مزود مرخص واتفاق ووثائق API/Sandbox وبيانات الاختبار والتسوية.

## أماكن التخصيص

- `app/(tabs)/index.tsx`: واجهة Android/iOS الأصلية وتدفق المحاكاة ومشاركة صورة الإيصال.
- `app/(tabs)/index.web.tsx` و`components/tahwelaty-web/`: نسخة المتصفح، والمكونات، والتنسيقات، ومسارات الأصول، ومشاركة PNG.
- `app/+html.tsx`, `public/manifest.webmanifest`, `public/service-worker.js`, `public/icons/`: تعريف PWA وأيقوناته ومسار Service Worker.
- `.github/workflows/deploy.yml`: تصدير Expo إلى `dist` ونشر GitHub Pages مع بادئة اسم المستودع.
- `components/tahwelaty/data.ts`: الرصيد صفر جنيه، والفواتير والأمثلة، ودالة إخفاء المعرفات.
- `lib/payments/provider-contract.ts`: عقد الربط المستقبلي مع بقاء المدفوعات الحقيقية معطلة.
- `eas.json`: إعداد بناء APK داخلي عبر لوحة المشروع.
- `assets/images/`: أيقونات العلامة والصورة المرجعية.

قبل إضافة مدفوعات حقيقية، يلزم اختيار مزود مناسب والتعاقد معه والحصول على وثائق Sandbox، ثم تنفيذ واختبار الإشعارات والتسوية والأخطاء والحدود والاسترداد ومراجعة المتطلبات التنظيمية والأمنية. لا تفعّل مدفوعات حقيقية بمجرد تغيير علم في الواجهة.
