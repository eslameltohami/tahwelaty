# TAHWELATY — تحويلاتي

نموذج واجهات عربي RTL لتحويل الأموال وسداد الفواتير، يعمل على Expo/React Native للويب وAndroid وiOS.

## الحالة الحالية

هذه **نسخة واجهات تجريبية** وليست تطبيقًا ماليًا جاهزًا للإطلاق. الأرصدة والعمليات محاكاة محلية. لا يوجد مزود دفع أو اتفاق API أو Sandbox، ولا يُرسل التطبيق أي معاملة أو شكوى إلى بنك أو شركة تحصيل. لا تستخدم بياناتًا مالية حقيقية عند تجربة النماذج.

تظهر فوري وأمان ومصاري وe-Khales كأمثلة سوقية غير مرتبطة بـ TAHWELATY. تظهر شركات الفواتير كخيارات تصميمية فقط؛ لا يوجد استعلام فاتورة أو دفع فعلي. راجع [`docs/egypt-biller-sources.md`](docs/egypt-biller-sources.md) لمصادر الأسماء.

PIN التجريبي يحتفظ به التطبيق في الذاكرة خلال الجلسة فقط ولا يحمي أموالًا. مسار التحقق البيومتري يستخدم Expo Local Authentication على هاتف يدعم بصمة أو Face ID ومسجل عليه قياس حيوي. واجهة الويب لا تختبر حساسًا فعليًا. لا تعتبر هذه النسخة تطبيقًا آمنًا للإنتاج.

تقتصر أرقام الهاتف والمشترك على بيانات اختبار رقمية، وتُخفى معظم خاناتها في السجل والإيصال التجريبي، ثم تُمسح حقول النموذج بعد بدء المحاكاة. مع ذلك، لا تدخل بيانات حقيقية في النسخة التجريبية.

## التشغيل

```bash
pnpm install
pnpm dev
```

يبدأ الأمر Expo Web على المنفذ 8081 وخادم القالب على 3000. لا تعتمد تدفقات TAHWELATY المالية على خادم القالب، ولا تحتوي على تكامل دفع حقيقي. افتح مشروع Expo في Expo Go على هاتف Android أو iPhone لمعاينة واجهات الجهاز؛ يجب اختبار البصمة على جهاز حقيقي مناسب.

## أماكن التخصيص

- `app/(tabs)/index.tsx`: التنقل، شاشة البداية المتحركة، تدفق المحاكاة، وحوارات PIN والإيصال.
- `components/tahwelaty/screens.tsx` و`components/tahwelaty/ui.tsx`: الشاشات ومكوّنات الواجهة العربية.
- `components/tahwelaty/data.ts`: أسماء مفوتري الفواتير ومزودي التحصيل المعروضة كأمثلة.
- `lib/payments/provider-contract.ts`: حدود الربط المستقبلي، مع إيقاف المدفوعات الحقيقية افتراضيًا.
- `assets/images/`: الأيقونات ومرجع التصميم المستخرج من صورة المستخدم.
- `app.config.ts`: إعدادات Expo واسم التطبيق وأذونات Face ID وأصول العلامة.

قبل إضافة مدفوعات حقيقية، يجب اختيار مزود مناسب، والتعاقد معه، والحصول على وثائق Sandbox، ثم تنفيذ التكامل والتحقق من الإشعارات والتسوية والأخطاء والحدود والاسترداد، ومراجعة المتطلبات التنظيمية والأمنية. لا تفعّل مدفوعات حقيقية بمجرد تغيير علم في الواجهة.
