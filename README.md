# TAHWELATY — تحويلاتي

واجهة عربية RTL لتجربة مسارات تحويل الأموال وسداد الفواتير. يتضمن المشروع مسارين منفصلين: واجهة React Native لتطبيق Android وiPhone، وواجهة React DOM مستقلة للمتصفح مع دعم إضافة الشاشة الرئيسية.

## الحالة وحدود الأمان

هذه **نسخة واجهات تجريبية** وليست خدمة مالية أو تطبيقًا جاهزًا للإطلاق. الأرصدة والعمليات محاكاة محلية، ولا يوجد مزود دفع أو اتفاق API أو Sandbox، ولا يرسل التطبيق أي معاملة أو شكوى إلى بنك أو شركة تحصيل. لا تستخدم بياناتًا مالية حقيقية عند تجربة النماذج.

تظهر فوري وأمان ومصاري وe-Khales كأمثلة سوقية غير مرتبطة بـ TAHWELATY. وتظهر شركات الفواتير كخيارات تصميمية فقط؛ لا يوجد استعلام فاتورة أو دفع فعلي. مصادر الأسماء موثقة في [`docs/egypt-biller-sources.md`](docs/egypt-biller-sources.md).

PIN التجريبي يُحتفظ به في ذاكرة الجلسة فقط ولا يحمي أموالًا. مسار التحقق البيومتري يستخدم Expo Local Authentication على هاتف يدعم بصمة أو Face ID ومسجل عليه قياس حيوي. واجهة المتصفح لا تختبر حساسًا فعليًا. لا تعتبر هذه النسخة تطبيقًا آمنًا للإنتاج.

تقتصر أرقام الهاتف والمشترك على بيانات اختبار رقمية، وتُخفى معظم خاناتها في السجل والإيصال التجريبي، ثم تُمسح حقول النموذج بعد بدء المحاكاة. مع ذلك، لا تدخل بيانات حقيقية في النسخة التجريبية.

## معاينة الويب والإضافة إلى الشاشة الرئيسية

مصدر واجهة المتصفح هو `app/(tabs)/index.web.tsx` ومكونات `components/tahwelaty-web/`. أما `app/(tabs)/index.tsx` فيظل مسار Android/iOS كما هو. افتح Preview للمشروع من لوحة المشروع لعرض نسخة الويب على متصفح الهاتف أو الكمبيوتر؛ تعمل معاينة Expo على المنفذ 8081.

لتثبيت الواجهة على هاتف Android، افتح معاينة HTTPS في Chrome واضغط زر «إضافة للشاشة» داخل التطبيق أو اختر «تثبيت التطبيق/إضافة إلى الشاشة الرئيسية» من قائمة المتصفح. على iPhone، افتح المعاينة في Safari، اضغط «مشاركة»، ثم «إضافة إلى الشاشة الرئيسية».

تضم الواجهة Manifest وأيقونات هاتف. الـ Service Worker يعمل بوضع الشبكة فقط ولا يخزّن حقول الإدخال أو المعاملات، لذلك لا يعد هذا الإصدار بتشغيل كامل دون اتصال. توفر خيار التثبيت يعتمد على المتصفح ونظام التشغيل، ومعاينة المشروع ليست نشرًا عامًا أو رابط متجر.

## تشغيل المشروع

```bash
pnpm install
pnpm dev
```

يبدأ الأمر Expo Web على المنفذ 8081 وخادم القالب على 3000. لا تعتمد تدفقات TAHWELATY المالية على خادم القالب ولا تحتوي على تكامل دفع حقيقي. لمعاينة التطبيق الأصلي، افتح المشروع في Expo Go على هاتف Android أو iPhone؛ ويجب اختبار البصمة على جهاز حقيقي مدعوم.

فحوص التطوير:

```bash
pnpm check
pnpm lint
pnpm exec expo export --platform web
```

## أماكن التخصيص

- `app/(tabs)/index.tsx`: شاشة Android/iOS الأصلية وتدفق المحاكاة.
- `app/(tabs)/index.web.tsx`: مدخل نسخة المتصفح الخاصة.
- `components/tahwelaty-web/`: شاشات React DOM ومكونات الحقول والحوار وCSS المتجاوب.
- `app/+html.tsx`: لغة واتجاه الصفحة ووسوم PWA وiOS.
- `public/manifest.webmanifest`, `public/service-worker.js`, `public/icons/`: تعريف التثبيت وأيقونات PWA ومعالجة التنقل الشبكي.
- `public/manus-routes.json`: المسارات المعلنة لصفحات المشروع.
- `components/tahwelaty/data.ts`: أسماء مفوتري الفواتير ومزودي التحصيل المعروضة كأمثلة، ودالة إخفاء المعرفات.
- `lib/payments/provider-contract.ts`: حدود الربط المستقبلي مع بقاء المدفوعات الحقيقية معطلة.
- `assets/images/`: الأيقونات ومرجع التصميم الذي أرسله المستخدم.
- `app.config.ts`: إعدادات Expo واسم التطبيق وأذونات Face ID وأصول العلامة.

قبل إضافة مدفوعات حقيقية، يجب اختيار مزود مناسب والتعاقد معه والحصول على وثائق Sandbox، ثم تنفيذ التكامل والتحقق من الإشعارات والتسوية والأخطاء والحدود والاسترداد، ومراجعة المتطلبات التنظيمية والأمنية. لا تفعّل مدفوعات حقيقية بمجرد تغيير علم في الواجهة.
